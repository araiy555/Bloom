# Bloom — プロダクト要件定義（PRD）

AI学習・生成プラットフォーム

---

## 1. プロダクト概要

ユーザが自分のデータ（画像・PDF・Excel・テキスト等）をアップロードし、用途を選択することで、AIモデル（またはAIエージェント）を作成・利用・共有・販売できるプラットフォーム。

## 2. プロダクト目的

- AI学習・構築の専門知識を不要にする
- 誰でもAIを作成できる環境を提供する
- 作成したAIを公開・共有・販売できる市場を作る

## 3. コアコンセプト

> **「AIを作るのではなく、AIを育てて使う」**

## 4. ユーザ機能要件

### 4.1 ユーザ管理
- メール or OAuthログイン（Googleなど）
- ユーザごとのプロジェクト管理
- セッション管理

### 4.2 プロジェクト管理
ユーザは複数のAIプロジェクトを作成可能。

プロジェクト属性:
- 名前
- タイプ（漫画 / Excel / 営業 / その他）
- データセット
- AI設定
- ステータス（未作成 / 学習中 / 完成）

### 4.3 データアップロード
対応データ:
- 画像（jpg/png）
- PDF
- CSV / Excel
- テキスト
- URL（将来拡張）

機能:
- アップロード
- 自動分類（AIによる）
- 前処理（分割・整形）

### 4.4 AI作成フロー

ユーザ操作:
1. プロジェクト作成
2. データ投入
3. 目的選択
4. AI生成開始

システム内部処理:
- データ解析
- タスク判定
- 学習方式選択（RAG / LoRA / Fine-tune）
- モデル生成 or 推論設定

### 4.5 AIアシスト機能（重要）
AIがユーザをガイド:
- 不足データの指示
- データ品質評価
- 学習可能性診断
- 最適化提案

例:
- 「横顔データが不足しています」
- 「このデータは分類『漫画』に適しています」

### 4.6 AI実行・利用
- チャットUI
- 生成API
- プレビュー機能

### 4.7 公開・共有機能（後期）
- 非公開（個人利用）
- URL共有
- ギャラリー公開
- マーケット掲載

### 4.8 マーケット機能（将来）
- 他ユーザが作ったAIを購入・利用
- サブスクモデル
- 収益分配

## 5. システム要件

### 5.1 アーキテクチャ
- フロントエンド: Next.js
- バックエンド: FastAPI
- DB: PostgreSQL
- ストレージ: S3互換
- AI: 外部API利用

### 5.2 AI連携
- OpenAI API
- Anthropic API
- ローカルLLM（将来対応）

### 5.3 学習方式（抽象化）
ユーザからは非表示:
- RAG（知識ベース）
- LoRA（画像系）
- Fine-tuning（将来）
- プロンプト生成

## 6. 非機能要件
- スケーラブル設計（マルチユーザ対応）
- APIキー方式（ユーザ負担コスト）
- 低コスト運用
- ブラウザ完結UI

## 7. UI方針
- ブロック型（子供でも使える）
- ドラッグ＆ドロップ
- 1画面中心設計
- 専門用語を排除

## 8. 成功条件
- 非エンジニアがAIを作れる
- 5分以内でAIが生成できる
- 作ったAIが使える

## 9. スコープ

### MVP でやること
- ユーザ
- プロジェクト
- データアップロード
- AI生成（APIベース）
- シンプルUI

### MVP でやらないこと
- 本格学習エンジン
- GPU管理
- 高度なマーケット
- 自動収益分配

## 10. 本質まとめ

このプロダクトはこういうもの:

- **AI学習OSではなく**
- **AI作成インターフェース**
